## Electron App 优化分析（tradingtool-elec / MT5 Trader Workbench）
对 `F:\ai\workbench-gemini` 做了架构体检，定位到几个真实瓶颈，按优先级归类：

### P0 — 性能/架构硬伤
- **事件循环被 MT5 同步调用阻塞**：`python_service/app/services/streaming_service.py` 的 `streaming_loop()` 是 `async def`，循环体内却同步调用 `mt5.terminal_info()` / `account_info()` / `get_symbol_quotes()`（持有 threading.RLock）。每次调用冻结整个 uvicorn 事件循环，/health、所有 HTTP、WS 广播一起排队。
- **`parent_process_watchdog` 每 2s 跑 `tasklist`（Windows 全进程枚举，数百 ms）**：应改 `psutil.pid_exists` / ctypes `OpenProcess`，并移出事件循环。
- **渲染层 8 路独立 `setInterval`（各 2s）打后端**：dashboard/PriceAlerts/IndicatorAlerts/Volatility/OrderBroadcast/OrderSync/TradingReview/status-bar。部分页面切换后定时器未清理；`dashboard-store` 的 `pollingInterval` 是模块级单例，多组件 startPolling 互相 clearInterval。
- **后端已有 WebSocket `/ws/overlay` 每秒推行情，前端未复用**——这是统一数据通道的基础。
- **零懒加载 + 1.6MB 单包**：24 页面全量静态 import 进 `App.tsx`，`lightweight-charts` 进主包。应 `React.lazy` + `Suspense` 拆包，图表库动态 import。

### P1 — 启动体验
- `createWindow()` 先 `await waitForBackendHealth()`（最长 15s）再建窗口，期间无 splash；`lifespan` 里同步 `get_mt5_client(allow_launch=True)` 启动 MT5 终端挡启动。
- `before-quit` 里 `destroyTray()` 过早销毁托盘（若 quit 被 coordinator 取消则无法再退出），应移到 `will-quit`。
- Electron 30（2024-04）过旧，建议升级到最新稳定版。

### P2 — 安全边界（交易软件，资金风险）
- `src/preload/index.ts` 暴露完整 `ipcRenderer.invoke/send/on`（无白名单），XSS 即任意调用主进程。
- `registerFileProtocol('local-file')` 无路径校验 → 任意本机文件读。
- 后端 CORS `allow_origins=['*']` 且 127.0.0.1:8765 无鉴权 → 恶意网页可跨域读账户/持仓，甚至触发下单。
- overlay 窗口 `sandbox: false`（与主窗口不一致）。
- `killBackendOnPort()` 每次冷启动 PowerShell 杀端口进程，慢且可能误杀。

### P3 — 质量
- `api_refresh_interval` 渲染层读取但不在 `settings.default.json` 中（schema 漂移）。
- 无 lint / typecheck 脚本；Python 测试未接进 `npm test`。
